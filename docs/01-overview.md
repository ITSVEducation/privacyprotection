## 1. 背景・目的

社内でAIサービスにテキストやファイルを渡す際、個人情報や会社固有の機密情報を含めることができない。
人手による事前チェックは負担が大きいため、**完全ローカルで動作する自動マスキングアプリ**を作成する。
マスクした情報はAIの回答受領後に元へ復元できるようにする。

## 1.1 脅威モデル（守るもの・守らないもの）

本アプリの目的は「**個人情報・機密情報がクラウド上のAIサービスに渡ること**」を防ぐことである。

- **守る**: マスク済ファイル・テキストに個人情報が残ってAIに送信されること
- **守らない**: ローカルPC内に個人情報が存在すること自体（元ファイルも対応表もローカルにあることは前提であり問題としない）

この前提から、対応表は**暗号化せず、人間が見て分かりやすい平文形式**とする。PC盗難・マルウェア等による
ローカルデータ漏洩は本アプリのスコープ外であり、OSレベルの対策（BitLocker等）でカバーする。

> この脅威モデルが、対応表を平文CSVにする（[03](03-masking-spec.md)）、レポートに実値を出さない
> （[04](04-ui-and-operations.md)）といった設計判断の根拠になっている。

## 2. 要件

### 2.1 機能要件

| # | 要件 |
|---|------|
| F-1 | 定型PII（電話番号・メールアドレス・住所・郵便番号・マイナンバー・クレジットカード番号等）を正規表現パターンで検出する |
| F-2 | カスタム辞書（取引先名・製品コード・社内用語等）に登録された語句を検出する |
| F-3 | 日本語固有表現抽出（NER）により、辞書未登録の人名・組織名・地名を検出する |
| F-4 | テキスト系ファイル（.txt / .csv / .json / .md 等のプレーンテキスト）をマスクできる |
| F-5 | Office系ファイル（.xlsx / .docx / .pptx）を書式を保持したままマスクできる |
| F-6 | クリップボードのテキストを直接マスクし、クリップボードに戻せる |
| F-7 | 指定フォルダ配下を再帰的に一括マスクできる |
| F-8 | マスク方式を「可逆（代替トークン＋対応表）」「不可逆（塗りつぶし）」から選択できる |
| F-9 | 可逆方式では対応表（人間可読なCSV）を出力し、マスク済ファイルまたはAI回答テキストを元に復元できる |
| F-10 | マスク実行前に検出結果をプレビューし、誤検出の除外・検出漏れの手動追加ができる |
| F-11 | 「確認なしで即変換」オプションを選択できる。即変換時も処理後レポートを必ず表示する（→ [04](04-ui-and-operations.md)） |
| F-12 | カスタム辞書をGUIで編集でき、CSVインポートに対応する |
| F-13 | 検出カテゴリ（人名・組織名・地名等）を個別にON/OFFできる |

### 2.2 非機能要件

| # | 要件 |
|---|------|
| N-1 | 完全ローカル実行。ネットワーク通信を行うコードを一切含めない（→ [04](04-ui-and-operations.md)） |
| N-2 | Windows専用。単体exe（またはワンフォルダ）形式で配布。MLモデル同梱でサイズ500MB前後を許容 |
| N-3 | ITに詳しくない社員でも使えるGUI（ドラッグ&ドロップ中心） |
| N-4 | 大きなファイルの処理中もUIが固まらない（ワーカースレッド＋進捗表示） |
| N-5 | NER検出は完全ではないことをUI上に常時注記する |
| N-6 | 元ファイルは決して変更しない。出力は常に別ファイル |

### 2.3 対象外（スコープ外）

- PDFファイル（テキスト層抽出・OCRとも対象外）
- 埋込画像内の文字（OCRしない）
- Mac / Linux対応
- 対応表の暗号化（1.1 の脅威モデルにより不要と判断）
- ローカルPC自体のセキュリティ（盗難・マルウェア対策）
- 社内サーバー・Web版
