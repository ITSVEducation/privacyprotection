# 解析中ローディング表示と GUI フリーズ解消 — 設計

## 問題

マスク実行後、解析（NER）が終わるまでウィンドウが「応答なし」になる。

原因は2つ:

1. **単一ファイル・クリップボードの解析が GUI スレッドで実行される。**
   `MainWindow._dispatch_paths` / `_mask_clipboard` が `pipeline.analyze_file` /
   `analyze_text`（GiNZA NER を含む）を直接呼ぶ。フォルダ一括だけが
   `MaskWorker`（QThread）で動いている。
2. **GiNZA モデルが実行のたびに再ロードされる。**
   `_build_pipeline()` が毎回新しい `NerDetector` を作り、`NerDetector` は
   インスタンスごとに `spacy.load("ja_ginza")` を遅延ロードする。
   モデルロードは数秒〜十数秒かかるため、毎回の実行が長時間フリーズする。

## 決定事項（ユーザー承認済み）

- 根本対応: 解析のワーカースレッド化 + モデルのプロセス内キャッシュ
- ローディング表示はメイン画面内（既存進捗バーの不確定モード + ラベル）。
  モーダルダイアログは使わない。

## 設計

### 1. core/ner.py — GiNZA モデルのプロセス内キャッシュ

モジュールレベルで一度だけロードし、全 `NerDetector` インスタンスで共有する。

- `_NLP`（キャッシュ）と `threading.Lock` をモジュールに置き、
  `NerDetector._load()` はキャッシュ済みモデルを返す。
- ロックはワーカースレッドと GUI スレッドの二重ロード防止のため。
- 挙動の変化: 2回目以降のマスク実行でモデルロードが発生しなくなる。
  初回のみ従来どおりロード時間がかかる（が、ワーカー化により UI は固まらない）。

### 2. gui/main_window.py — 単一ファイル／クリップボード解析のワーカー化

遅いのは NER を含む解析だけ。解析を `MaskWorker` で実行し、その前後
（断片読み込み・意図判定・プレビュー表示・マスク書き出し）は従来どおり
GUI スレッドで行う。プレビュー確定後の `mask_file` / `mask_text` は
検出済みリストを渡すため NER を再実行せず高速。

- **単一ファイル（複数ドロップ含む）**: `_dispatch_paths` のマスク経路を
  逐次キュー処理に変える。先頭ファイルの `analyze_file` をワーカーで実行し、
  完了ハンドラでプレビュー→マスク→次のファイルへ、と1件ずつ進める。
  ファイル単位の失敗は従来どおりダイアログ1つに留め、残りの処理を続ける。
- **クリップボード**: `_mask_clipboard` の `analyze_text` をワーカーで実行し、
  完了ハンドラでプレビュー→`mask_text`→完了ダイアログ。
- **復元経路は変更しない**（NER を使わず高速なため）。
- `_run_worker` の「実行中は新規実行を拒否」ガードは維持する。キュー連鎖で
  直前のワーカーの `finished_ok` から次を起動する際は、スレッド終了を
  `wait()` で確定させてから差し替える（`finished_ok` 発火時点では
  `isRunning()` がまだ真のことがあるため）。

### 3. ローディング表示

- 進捗バーの上に状態ラベル（既定は非表示）を追加する。
- 解析ワーカー実行中: 進捗バーを不確定モード（`setRange(0, 0)`、バーが
  流れるアニメーション）にし、ラベルに「解析中…」＋対象名（ファイル名 or
  「クリップボード」）を表示する。**ファイル名以外の検出値は表示しない**
  （不変条件: レポート・表示にはカテゴリ・件数・ファイル名のみ）。
- フォルダ一括: 最初は不確定モードで始まり、`progress` シグナル受信時に
  確定モード（`setRange(0, total)`）へ切り替え、ラベルに
  「処理中: <ファイル名> (i/total)」を表示する。
- 実行中の操作無効化は既存の `_set_controls_enabled(False)` を流用。
- 完了・失敗時はバーとラベルを隠し、操作を再有効化する。

## テスト

- `tests/core/test_ner.py` に追加: `spacy.load` をモンキーパッチして呼び出し
  回数を数え、複数の `NerDetector` インスタンスでもロードが1回であることを
  固定する（実モデル不要、キャッシュはテスト内でリセット）。
- GUI 層は既存方針どおり手動確認（QApplication 必須のスレッド連携は
  ユニットテスト対象外）。手動確認手順: 大きめのテキストファイルをドロップ
  →「解析中…」表示とバーのアニメーション、ウィンドウ移動が可能なこと、
  2回目実行が即時に始まることを確認。

## 対象外（YAGNI）

- キャンセルボタン（解析は中断不能な spaCy 呼び出しで、要望もない）
- スプラッシュ画面・起動時の事前ロード（初回のみの話で、ワーカー化で UI は
  固まらない）
- 復元経路のワーカー化
