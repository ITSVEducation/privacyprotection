# 同じ語のまとめ表示と全出現マスク — 設計書

- 日付: 2026-07-27
- 対象: `core/spans.py`, `gui/preview_dialog.py`
- 関連仕様: `docs/03-masking-spec.md`（§4.2 重複解決 / §4.4 トークン）,
  `docs/04-ui-and-operations.md`（§6.2 プレビュー画面）
- 前提: [2026-07-24 プレビュー編集の直接操作化](2026-07-24-preview-editing-and-clipboard-preview-design.md)

## 1. 背景と目的

プレビュー右側の検出一覧は「検出スパン1件につき1行」で表示している。同じ値
（例: 人名「谷　直明」）が本文中に複数回出現すると、同一の値がそれぞれ別の
検出として複数行に並び、ユーザーには「同じ語なのに分かれている」と映る。

また、左ペインでのドラッグ手動追加は選択した**1箇所だけ**を検出として追加する
ため、同じ語が他の箇所にも出現していても、その語を検出器が拾っていなければ
マスクされない。「特定の語を見つけたら本文全体で同じようにマスクしたい」という
要望に応えられていない。

なお `core/masker.py` は同一の値（`Detection.text`）に常に同一トークンを割り当てる
ため、同じ語の各出現が検出として存在すればマスク**出力自体は既に一貫している**。
本設計が足すのは、(a) 一覧表示のまとめ方と、(b)「1つ見つけたら全出現に広げる」
編集操作であり、トークン割り当ての仕組みは変更しない。

## 2. スコープ

**やること**
- プレビュー画面に「同じ語をまとめて扱う」チェックボックスを追加（既定OFF）。
- ONのとき: 一覧を値ごとに集約表示／ドラッグ追加を全出現へ展開／ハイライトの
  クリック無効化と一覧のチェック・カテゴリ変更を同じ値すべてへ適用。
- ある値の全出現位置を返す純粋関数を `core/spans.py` に追加。

**やらないこと（YAGNI）**
- `core/masker.py` の置換・トークン割り当ては変更しない（同一値＝同一トークンは
  既に成立）。
- 自動検出（NER/パターン/辞書）の結果を全出現へ**自動**展開はしない。全出現
  展開はユーザーがドラッグ追加した語に対して、チェックボックスONのときだけ
  行う（過剰マスクを避けるため。§6 参照）。
- チェックボックスの状態は永続化しない（プレビューを開くたび既定OFF）。
- あいまい一致・正規化一致はしない（完全一致のみ。§6 参照）。

## 3. モード仕様

プレビュー画面上部にチェックボックス **「同じ語をまとめて扱う」**（既定OFF）を
置き、その状態で画面全体の粒度を切り替える。表示粒度と操作粒度は常に一致させる
（集約表示なのにクリックが1箇所だけ無効化する、といった不一致を作らない）。

| 操作 | OFF（既定・個別） | ON（まとめて） |
|---|---|---|
| 一覧表示 | 出現ごとに1行（現状のまま） | 同じ `(値, カテゴリ)` を1行に集約。件数を `×N`（N>1のとき）で付す |
| ドラッグ追加 | 選択した1箇所だけをカスタム追加 | 選択した語の**全断片・全出現**をカスタム追加 |
| ハイライトのクリック | その1箇所の検出を無効化 | その値の全出現をまとめて無効化 |
| 一覧のチェック切替 | その1件のみ有効/無効 | 同じ値の全出現に適用 |
| カテゴリ変更（一覧の右クリック） | その1件のみ | 同じ値の全出現に適用 |

- チェックボックスを切り替えると `_refresh()` で表示し直す。既存の検出データは
  作り替えない（ONにしても自動検出を遡って全出現へ展開はしない。§2）。
- ONで新規にドラッグ追加した語だけが全出現へ展開される。展開後にOFFへ戻すと、
  展開で増えた各出現は個別の行として現れる（データとしては通常の検出のため）。

## 4. core への追加

`core/spans.py` に純粋関数を追加する（既存の区間ユーティリティ群と同じ場所。
検出器・マスカーには依存しない文字列区間の計算のみ）。

```python
def find_occurrences(text: str, value: str) -> list[tuple[int, int]]:
    """text 中の value の完全一致・非重複の全出現を (start, end) で返す。

    value が空なら空リスト。重なり得る自己出現（"aa" in "aaa"）は、直前の
    一致の末尾から次を探すことで非重複に列挙する。
    """
```

実装は `str.find` を末尾送りで回すだけ。あいまい一致はしない（§6）。

## 5. GUI（preview_dialog.py）の変更

`PreviewDialog` に以下を追加する。既存の直接操作（ドラッグ追加＝カスタム、
クリック＝無効化、右リスト右クリック＝カテゴリ変更、断片境界ガード）は
2026-07-24 設計のまま保ち、モードによる分岐を被せる。

- **チェックボックス** `self.group_same`（「同じ語をまとめて扱う」, 既定 unchecked）。
  `toggled` → `_refresh()`。
- **`_refresh()`**: `group_same` がONなら、`self.detections` を走査して
  `(text, category)` ごとに集約し、グループ1件につき1行（`×N` 付き）を出す。
  行の `UserRole` にはグループ内の検出リスト（またはキー）を持たせ、チェック状態は
  「グループ内に有効な検出が1つでもあるか」で決める。ハイライトは従来どおり
  有効な各検出のスパンに色を付ける（＝全出現がハイライトされる）。OFFなら現状の
  出現ごと1行のまま。
- **`_on_item_toggled(item)`**: OFFは現状（その1件）。ONはグループ内の全検出の
  `enabled` を新しいチェック状態に合わせる。
- **`_change_category(...)`**: OFFはその1件。ONは同じ `(値)` の全検出のカテゴリを
  変更（集約キーがカテゴリを含むため、変更後は別グループに移る）。
- **`_on_drag_select(start, end)`**: OFFは現状（選択1箇所をカスタム追加）。ONは
  選択文字列 `value` を取り出し、全断片について `find_occurrences(frag.text, value)`
  で全出現ぶんの `Detection(source="manual", category=CUSTOM)` を追加（既に同じ
  スパンの検出があれば重複追加しない）。断片境界をまたぐ選択の警告は従来どおり。
- **`_on_click_disable(pos)`**: OFFは現状（その位置の有効な検出1件を無効化）。ONは
  その位置の検出の**値**を特定し、全断片でその値を持つ有効な検出をすべて無効化。

`find_occurrences` は `core/spans.py` から import する。`PreviewDialog` は既に
`core.models` の素のデータ型を import しており（2026-07-24 設計の注記参照）、本関数も
検出器・マスカーの組み立てを伴わない純粋な区間ユーティリティであるため、同じ
方針で import してよい（GUIが業務ロジックを再実装するわけではない）。

## 6. リスク・留意点

- **過剰マスク**: 全出現マスクは完全一致の部分文字列で行うため、短い語（例:
  「谷」）が別の語の一部（「谷川」）に一致してしまう恐れがある。これを避けるため、
  全出現展開は**ユーザーが明示的にドラッグ追加した語**に対して、チェックボックス
  ONのときだけ行う（自動検出は展開しない）。ユーザーは選択とチェックで意図を
  明示しているため、この範囲なら許容できる。
- **表示と操作の粒度一致**: 集約表示（ON）では必ず操作も値単位にする。片方だけ
  値単位にすると、行はチェック済みなのに一部出現だけ無効、という不整合になる
  （本設計はこれを避けるために単一のモードトグルにしている）。
- **トークンの一貫性**: モードに関わらず、同一値には同一トークンが割り当てられる
  （`core/masker.py` の既存挙動）。本設計は表示・編集のみでこの仕組みに触れない。
- **モード切替時のデータ**: ONは既存検出を作り替えない（遡及展開しない）。ONで
  追加した展開ぶんはOFFで個別行として見える。これは仕様（データはあくまで通常の
  検出スパン群）。

## 7. テスト

GUI 層は本プロジェクトの方針どおり手動確認。追加する純粋関数はユニットテスト。

- `find_occurrences`:
  - 複数出現を全て返す（位置が正しい、`text[s:e] == value`）。
  - 出現なし → 空。空 value → 空。
  - 重なり得る自己出現（"aa" in "aaaa" は2件で非重複）。
- 手動確認（`uv run python -m privacyprotection.gui.app`、既定OFF）:
  1. 同じ人名が複数回出る文でプレビュー → OFFでは出現ごとに行、チェックONに
     すると1行 `×N` に集約されることを確認。
  2. ON状態で1箇所をドラッグ追加 → 全出現がハイライトされ、1行に集約されること。
  3. ON状態でハイライトのどれかをクリック → 全出現がまとめて無効化され、行の
     チェックも外れること。OFFでは1箇所だけ無効化されること。
  4. マスク実行 → 同じ語が全て同一トークンになっていること（従来どおり）。
