# メイン画面のUI簡素化 — 意図の自動判定＋詳細設定の折りたたみ

## 目的

メイン画面を「初回の人はドロップ or Ctrl+V だけで正しく使え、詳しい人は1アクションで
詳細設定に到達できる」構成にする。現状の課題:

- 「マスク/復元」「可逆/不可逆」「確認なしで即変換」が最上部に並び、初回の人には
  どれを触ればよいか・今どういう動きをするのかが読み取れない
- クリップボード処理がボタンのみで、Ctrl+V という自然な操作が使えない

方針（ブレインストーミングで確定済み）:

- 既定の動作は常に「可逆マスク＋プレビュー確認あり」
- Ctrl+V は現在のクリップボードボタンと同じフロー（解析→プレビュー→確定→コピー）
- マスク/復元のモード切替は廃止し、入力内容からの自動判定＋確認ダイアログに置き換える
- 上級者向け設定はメイン画面内の折りたたみパネルに集約し、内容と開閉状態を永続化する

## 1. メイン画面の構成

上から順に:

```
┌─────────────────────────────────────┐
│                                     │
│   ここにファイル／フォルダをドロップ      │  ← 主役。stretch で画面の大半を占める
│   （クリックで選択 ／ Ctrl+V で        │
│     クリップボードを処理）              │
│                                     │
├─────────────────────────────────────┤
│ [クリップボードを処理してコピー]          │
├─────────────────────────────────────┤
│ ▸ 詳細設定（可逆マスク・確認あり）        │  ← 折りたたみ。ヘッダーに現在の設定を要約
├─────────────────────────────────────┤
│ ⚠ 自動検出は完全ではありません…         │
└─────────────────────────────────────┘
```

- 「マスク/復元」ラジオ・「可逆/不可逆」ラジオ・「確認なしで即変換」チェックは
  メイン画面から消え、詳細設定パネル内へ移動する
- 「設定」「辞書を編集」ボタンも詳細設定パネル内へ移動する（メニューバーの
  「ツール」は現状どおり残す）
- クリップボードボタンのラベルはモード連動をやめ、常に
  「クリップボードを処理してコピー」とする（何をするかは自動判定）
- Ctrl+V をメインウィンドウのショートカット（`QShortcut`）として登録し、
  クリップボードボタンと同じ処理を起動する
- ドロップゾーンの案内文に Ctrl+V の存在を明記する

## 2. 意図の自動判定

判定は決定的なルールのみで行い、復元と判定した場合は必ず確認ダイアログを挟む。
判定を外した場合の影響は「1回余計に確認される」に留まる。

| 入力 | 判定条件 | 挙動 |
|---|---|---|
| テキスト（Ctrl+V／ボタン） | `TOKEN_RE`（`【種別_n】`）にマッチするトークンを含む | 「マスク済みテキストのようです。復元しますか？」→ はい: 対応表選択→復元 ／ いいえ: マスクのプレビューへ |
| テキスト | トークンなし | プレビュー→マスク（現行フロー） |
| ファイル | 隣に `<ファイル名>.pmap.csv` か `_folder.pmap.csv` がある、**または**抽出したテキスト断片にトークンを含む | 「マスク済みファイルのようです。復元しますか？」→ はい: 復元 ／ いいえ: マスクのプレビューへ |
| ファイル | 上記いずれもなし | プレビュー→マスク（現行フロー） |
| フォルダ | 直下に `_folder.pmap.csv` がある | 確認→はい: フォルダ内の対応ファイルを列挙して順次復元 ／ いいえ: 一括マスク |
| フォルダ | なし | 一括マスク（現行フロー） |

- 複数ファイルのドロップでは判定・確認をファイルごとに行う（現行の
  ファイル単位ループ・ファイル単位の例外捕捉を維持する）
- ファイルのトークン有無の確認は、マスク経路で必要になる断片抽出
  （`analyze_file` 相当）の結果を再利用し、二重に読み込まない
- 判定ロジックは純関数 `decide_action(...)` として `services/` に置き、
  ユニットテストを付ける（GUI は手動テスト中心のため、判定だけを
  テスト可能な層に出す）。ファイルシステムの状態（対応表の有無）と
  抽出済みテキストを引数で受け取り、判定結果の列挙値を返す
- 詳細設定に「動作: 自動判定（既定）／常にマスク／常に復元」のセレクタを置き、
  自動判定が邪魔なケースの逃げ道にする。「常にマスク」「常に復元」では
  判定と確認ダイアログを行わず、現行のモード固定と同じ挙動になる

## 3. 詳細設定パネルと永続化

- Qt 標準に disclosure ウィジェットがないため、`QToolButton`（矢印表示）＋
  コンテナ widget の表示切替で実装する
- パネル内容: 動作（自動判定/常にマスク/常に復元）、方式（可逆/不可逆）、
  確認なしで即変換、「設定…」「辞書を編集…」ボタン
- `AppConfig` に追加するフィールド:
  - `advanced_expanded: bool = False` — パネルの開閉状態
  - `action_mode: str = "auto"` — `"auto" | "mask" | "restore"`
- 既存の `mask_mode` / `skip_preview` は現行のまま流用する（初期値が
  「可逆＋確認あり」なので、初回起動時の既定は自動的に要件を満たす）
- ヘッダーの要約表示は畳んだ状態でも常に現在の動作を示す
  （例:「▸ 詳細設定（不可逆マスク・即変換）」）。既定
  （自動判定・可逆・確認あり）から変えている場合は要約を強調色にし、
  「不可逆のまま気づかない」事故を防ぐ

## 4. 変更しないもの

- プレビュー画面・レポート画面・設定ダイアログ・core / handlers / services の
  処理本体（`decide_action` の追加を除く）
- プライバシー不変条件（レポート・ダイアログに検出値そのものを載せない等）
- 実装時に `docs/04-ui-and-operations.md` §4.1 を同じコミット群で更新する

## テスト方針

- `decide_action` のユニットテスト: トークン有無×対応表有無×入力種別
  （テキスト/ファイル/フォルダ）×動作セレクタの組み合わせ
- `AppConfig` の新フィールドの load/save 往復テスト（既存 config.json に
  フィールドがない場合の既定値を含む）
- GUI（ショートカット登録・パネル開閉・確認ダイアログ）は現行方針どおり手動確認
