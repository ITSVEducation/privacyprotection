# 個人情報マスキングアプリ 設計書

作成日: 2026-07-23
ステータス: ドラフト（ユーザーレビュー待ち）

## 1. 背景・目的

社内でAIサービスにテキストやファイルを渡す際、個人情報や会社固有の機密情報を含めることができない。人手による事前チェックは負担が大きいため、**完全ローカルで動作する自動マスキングアプリ**を作成する。マスクした情報はAIの回答受領後に元へ復元できるようにする。

## 2. 要件

### 2.1 機能要件

| # | 要件 |
|---|------|
| F-1 | 定型PII（電話番号・メールアドレス・住所・郵便番号・マイナンバー・クレジットカード番号等）を正規表現パターンで検出する |
| F-2 | カスタム辞書（取引先名・製品コード・社内用語等）に登録された語句を検出する |
| F-3 | 日本語固有表現抽出（NER）により、辞書未登録の人名・組織名・地名を検出する |
| F-4 | テキスト系ファイル（.txt / .csv / .json / .md 等のプレーンテキスト）をマスクできる |
| F-5 | Office系ファイル（.xlsx / .docx / .pptx）を書式を保持したままマスクできる |
| F-6 | クリップボードのテキストを直接マスクし、クリップボードに戻せる |
| F-7 | 指定フォルダ配下を再帰的に一括マスクできる |
| F-8 | マスク方式を「可逆（代替トークン＋対応表）」「不可逆（塗りつぶし）」から選択できる |
| F-9 | 可逆方式では対応表（マッピングファイル）を出力し、マスク済ファイルまたはAI回答テキストを元に復元できる |
| F-10 | マスク実行前に検出結果をプレビューし、誤検出の除外・検出漏れの手動追加ができる |
| F-11 | 「確認なしで即変換」オプションを選択できる（フォルダ一括処理時に有用） |
| F-12 | カスタム辞書をGUIで編集でき、CSVインポートに対応する |
| F-13 | 検出カテゴリ（人名・組織名・地名等）を個別にON/OFFできる |

### 2.2 非機能要件

| # | 要件 |
|---|------|
| N-1 | 完全ローカル実行。ネットワーク通信を一切行わない |
| N-2 | Windows専用。単体exe（またはワンフォルダ）形式で配布。MLモデル同梱でサイズ500MB前後を許容 |
| N-3 | ITに詳しくない社員でも使えるGUI（ドラッグ&ドロップ中心） |
| N-4 | 大きなファイルの処理中もUIが固まらない（ワーカースレッド＋進捗表示） |
| N-5 | NER検出は完全ではないことをUI上に常時注記する |

### 2.3 対象外（スコープ外）

- PDFファイル（テキスト層抽出・OCRとも対象外）
- 埋込画像内の文字（OCRしない）
- Mac / Linux対応
- 対応表の暗号化（平文JSONで保存。ローカルPC内保管の運用でカバー）
- 社内サーバー・Web版

## 3. 技術選定

| 項目 | 選定 | 理由 |
|------|------|------|
| 言語 | Python 3.11+ | 日本語NERエコシステムが最も充実 |
| GUI | PySide6 (Qt) | ドラッグ&ドロップ、リッチなハイライト表示、実績 |
| NER | GiNZA (spaCy + ja_ginza) | 完全オフライン動作の日本語固有表現抽出 |
| xlsx | openpyxl | セル・コメント・ヘッダーフッター・図形テキストにアクセス可能 |
| docx | python-docx | 段落・表・ヘッダーフッターの書式保持置換 |
| pptx | python-pptx | スライド・ノートのテキスト置換 |
| パッケージング | PyInstaller | Windows単体配布 |
| テスト | pytest | コア層のユニットテスト |

## 4. アーキテクチャ

3層構成とし、**コア層はGUIに一切依存しない**。

```
┌─────────────────────────────────────────┐
│  GUI層 (PySide6)                          │
│  メイン画面 / プレビュー画面 / 設定画面      │
├─────────────────────────────────────────┤
│  コア層 (純Python・GUI非依存)               │
│  ・Detector: 検出エンジン                   │
│    - PatternDetector（正規表現）            │
│    - DictionaryDetector（カスタム辞書）      │
│    - NerDetector（GiNZA）                  │
│  ・Masker: 置換エンジン（可逆／不可逆）       │
│  ・Restorer: 復元エンジン（対応表→逆置換）    │
├─────────────────────────────────────────┤
│  ファイルI/O層 (Handler共通インターフェース)   │
│  TextHandler / XlsxHandler / DocxHandler / │
│  PptxHandler / ClipboardHandler /          │
│  FolderWalker（再帰一括処理）               │
└─────────────────────────────────────────┘
```

### 4.1 コア層の主要インターフェース

```python
@dataclass
class Detection:
    text: str          # 検出された文字列（例: "山田太郎"）
    category: str      # 種別（PERSON / ORG / LOC / PHONE / EMAIL / ADDRESS / CUSTOM 等）
    start: int         # テキスト断片内の開始位置
    end: int           # 終了位置
    source: str        # 検出元（pattern / dictionary / ner）
    enabled: bool      # プレビューでの採否（既定 True）

class Detector:
    def detect(self, text: str) -> list[Detection]: ...
    # 3つの検出器の結果をマージし、範囲が重複する場合は
    # 優先度 dictionary > pattern > ner で長い一致を採用する

class Masker:
    def mask(self, fragments: list[str], detections: list[list[Detection]],
             mode: Literal["token", "redact"]) -> tuple[list[str], MappingTable]: ...
    # token モード: 同一の値には文書全体（フォルダ一括時は一括処理全体）で
    #   同一トークンを割り当てる（例: 山田太郎 → 【人名_1】）
    # redact モード: 文字数に関係なく「●●●●」に置換。MappingTable は空

class Restorer:
    def restore(self, text: str, mapping: MappingTable) -> str: ...
    # テキスト中のトークンを対応表で逆置換。未知トークンはそのまま残し警告
```

### 4.2 ファイルI/O層の共通インターフェース

```python
class FileHandler(ABC):
    extensions: ClassVar[list[str]]
    def read_fragments(self, path: Path) -> list[Fragment]: ...
    def write_fragments(self, src: Path, dst: Path,
                        masked: list[Fragment]) -> None: ...
    # Fragment = ファイル内の位置情報（セル番地・段落番号等）付きテキスト断片。
    # write は元ファイルをコピーした上でテキスト部分のみ差し替え、書式を保持する
```

新しい拡張子への対応は Handler を1クラス追加するだけで完結させる。

### 4.3 対応表（マッピングファイル）仕様

- ファイル名: `<出力ファイル名>.pmap.json`（マスク済ファイルと同じフォルダに並置）
- 形式: 平文JSON

```json
{
  "version": 1,
  "created": "2026-07-23T10:00:00",
  "source_file": "議事録.docx",
  "mappings": [
    {"token": "【人名_1】", "original": "山田太郎", "category": "PERSON"},
    {"token": "【組織_1】", "original": "株式会社サンプル", "category": "ORG"}
  ]
}
```

- フォルダ一括処理時は、処理全体で1つの共有対応表を使い（同一人物は全ファイルで同一トークン）、ルートに `_folder.pmap.json` を出力する

## 5. データフロー

### 5.1 マスク時

1. ユーザーがファイル／フォルダをドロップ、またはクリップボード読込
2. Handler がテキスト断片（Fragment）を抽出（xlsx: セル・コメント・ヘッダーフッター・図形テキスト、docx: 段落・表・ヘッダーフッター、pptx: シェイプ・ノート）
3. Detector が検出リストを作成
4. プレビュー画面で原文ハイライト表示 → ユーザーが除外／手動追加（「確認なし」時はスキップ）
5. Masker が置換実行
6. 出力: `<元名>_masked.<拡張子>` ＋（可逆時）`.pmap.json`。元ファイルは変更しない

### 5.2 復元時

1. 復元対象を指定: マスク済ファイル、または AI回答を貼り付けたテキスト／クリップボード
2. 対応する `.pmap.json` を指定（同フォルダにあれば自動検出）
3. Restorer がトークンを逆置換。対応表にないトークンは残して警告表示

## 6. 画面構成

### 6.1 メイン画面

- 中央: ドラッグ&ドロップゾーン（ファイル複数可・フォルダ可）
- モード切替: マスク ／ 復元
- マスク方式: 可逆（トークン） ／ 不可逆（塗りつぶし）
- チェックボックス: 「確認なしで即変換」
- クリップボード操作: 「貼り付け→マスク→コピー」ワンクリックボタン
- 常時注記: 「自動検出は完全ではありません。重要なデータは必ずプレビューで確認してください」

### 6.2 プレビュー画面

- 左ペイン: 原文表示。検出箇所を種別ごとに色分けハイライト
- 右ペイン: 検出一覧（種別・値・件数）。チェックボックスで個別除外、種別単位の一括除外
- 手動追加: 左ペインでテキスト範囲選択 → 右クリック → 種別を選んで追加
- フォルダ一括時: ファイルごとにタブ表示（多数の場合は確認なしモードを促す）
- 確定ボタンで置換実行

### 6.3 設定画面

- カスタム辞書編集: 語句＋種別の表形式編集、CSVインポート／エクスポート
- 検出カテゴリのON/OFF（例: 地名を検出しない）
- 出力先設定: 元ファイルと同じフォルダ（既定） ／ 固定フォルダ
- 設定・辞書の保存先: `%APPDATA%/PrivacyProtection/`（JSON）

## 7. エラー処理

| ケース | 挙動 |
|--------|------|
| パスワード付き・破損Officeファイル | スキップし、処理完了後にエラー一覧で表示（一括処理は継続） |
| 未対応拡張子（フォルダ一括時） | スキップし、件数をサマリ表示 |
| 復元時に対応表にないトークン | そのまま残し、警告一覧に表示 |
| 巨大ファイル | ワーカースレッドで処理、進捗バー表示、キャンセル可能 |
| 出力先に同名ファイルが存在 | 連番付与（`_masked(2)` 等）で上書きしない |

## 8. テスト方針

- コア層（Detector / Masker / Restorer）: pytest でユニットテスト
  - パターン検出: 各PII種別の正例・負例
  - トークン一貫性: 同一値→同一トークン
  - **ラウンドトリップ: マスク→復元で原文と完全一致することを全対応形式で検証**
- ファイルI/O層: 実ファイルフィクスチャ（xlsx/docx/pptx/txt/csv）で書式保持を検証
- NER: 精度そのものはテストせず、「検出結果がDetection形式で返る」結合レベルの確認に留める
- GUI: 手動確認中心

## 9. 配布

- PyInstaller によるビルド（GiNZAモデル同梱、想定サイズ 500MB前後）
- 起動時間短縮のため one-folder 形式を第一候補とし、one-file（単体exe）は起動速度を検証の上で判断
- インストーラー不要（ZIP展開のみで動作）
